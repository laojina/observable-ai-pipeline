# 你自己怎么测：按顺序操作即可

这是操作清单，不是已经完成的人工测试证明。自动化测试已由工具运行，见验收记录。你实际操作后，才可以说“我运行并检查了这些场景”。

## 先记时间

在复核记录中写下实际开始和结束时间，只记录你实际操作、查看代码、思考的时间。不要把 AI 自动生成时间或长时间离开电脑的时间计作个人开发工时。

## 1. 打开页面，观察失败一次后成功

启动项目后打开 http://127.0.0.1:18080 。若页面能打开，不要再启动一个相同端口的服务。

填写：
- 素材标识：取一个从未用过的值，例如 manual-A-加上当前时间。
- 处理配置版本：v1。
- 每步耗时：1000。
- 超时：30000。
- 故障步骤：3。
- 前几次失败：1。

点击“提交异步任务”。先观察第三步出现 RETRY_WAIT 和错误，之后完成。最终应为 SUCCEEDED、4/4 步，尝试次数依次为 **1、1、2、1**。执行历史中应同时有失败和成功记录，不能只看到最终成功。

讲得清楚的重点：不是整条任务重跑，前两步已成功的产物保留，第三步重新尝试。

## 2. 相同输入再次提交，观察结果复用

保持刚才素材标识和版本不变，再提交一次。会生成新的 taskId，但执行历史应出现 REUSED；点击“查看产物”能看到 mock=true 的阶段 JSON。

注意：有可用产物时，故障注入不会执行，因此再次提交不一定再失败一次。这是命中复用，不是故障功能坏了。

## 3. 重试用完，再手动恢复

换一个全新素材标识。故障步骤保持 3，把“前几次失败”改为 3，其余不变。

最终任务 FAILED；第三步尝试 3 次，第四步没有执行。随后点“恢复 / 检查产物”，第四次尝试已超过配置的前三次注入失败，应完成。以前失败的执行记录仍存在。

重点：不是无限自动重试；自动预算用完后需要显式恢复，恢复追加预算而不是抹掉历史。

## 4. 观察超时，而不是让程序永远等

再次换新素材标识，把故障步骤改为 0、前几次失败改为 0；每步耗时设为 1500，超时设为 200。

第一步应该因 TimeoutException 失败，按预算重试后整个任务 FAILED；下游步骤不应执行。

重点：这是 Mock 可合作等待的超时演示，不代表能凭改数据库状态取消真实 GPU 或模型计算。

## 5. 改配置，旧结果不能随便复用

重新使用第 1 步的素材标识，但把版本改成 v2，关闭故障注入。此次应重新处理，执行记录不应把所有阶段标为旧版本 REUSED。

重点：缓存键需要包含计算配置和适配器版本，不能只看任务名。

## 6. 杀进程恢复、产物损坏：直接运行独立脚本

在项目目录执行：

```sh
python scripts/smoke.py
```

脚本自己启动 18083 端口的测试进程，第三步执行时强杀它，再用原文件库重启，最后篡改产物验证重建。**它不会关闭正在使用的 18080 演示服务，也不会操作你的 VidMind。**

如果机器已安装 Python 但 python 命令不可用，请使用实际 Python 完整路径。设置 JAVA_HOME 为 JDK 17+；必要时用 PIPELINE_JAVA 指定 java 可执行文件。

看到四行 PASS，才说明这次脚本运行通过；报告在控制台打印的 target/smoke-* 目录。查看 before-kill.json 和 after-restart.json：前两步尝试次数不变，第三步从 1 变 2，历史存在 ABANDONED。

Windows 强杀只能针对你启动并确认的测试进程，不要使用“结束全部 java.exe”的方式。

## 7. 想看全部自动回归

在项目目录执行：

```sh
mvn -gs settings-local.xml -s settings-local.xml verify
```

检查报告中的 Tests run: 8、Failures: 0、Errors: 0。运行环境或依赖问题需要修复后重新验证，不把“脚本存在”当作“脚本通过”。
