# 可观测、可恢复的动画素材处理管线 · 题 D

源码仓库：https://github.com/laojina/observable-ai-pipeline

这是一个独立的笔试项目。首版选择 **Java 17、Spring Boot、H2 文件库、单实例执行器和原生 HTML**。没有引入 MQ、Redis 或工作流引擎。

**实现范围：四个计算阶段全部为显式 Mock，产物为确定性的 JSON 清单，不提供实际视频抽帧、人物替换或生成效果。** 题 D 允许 Mock；本项目重点验证持久化、重试、重启恢复、产物完整性和执行历史。

## 运行

需要 JDK 17+、Maven 3.9+。在本目录执行：

```sh
mvn -gs settings-local.xml -s settings-local.xml clean verify
java -jar target/recoverable-pipeline-0.1.0.jar
```

浏览器打开 http://127.0.0.1:18080 。默认仅监听本机，不含登录认证，不应直接作为公网服务暴露。题目允许公开仓库交付，因此首版不要求公网部署。

Windows 也可以在本目录执行 `./start.ps1`（使用 JAVA_HOME 对应的 JDK），或在 IDEA 打开 pom.xml，运行 `dev.pipeline.Application`。已打包的本地版本位于 target/recoverable-pipeline-0.1.0.jar。

如果全局 Maven 镜像配置有异常，可使用项目的 settings-local.xml。它不改变全局配置。数据默认保存在当前工作目录下的 data/；重启必须使用相同工作目录或通过 `--pipeline.data=绝对路径` 指定原目录。不要用内存库验证重启恢复。

## 演示顺序

1. 创建唯一素材标识的任务，第三步设置失败一次，观察 RETRY_WAIT、错误和第二次成功。
2. 同样的素材与配置再次提交，观察每步执行记录 REUSED。
3. 用新的素材标识、每步 5000ms 提交；第三步 RUNNING 时强制结束 Java 进程，重新启动。
4. 验证前两步尝试次数不变，旧执行记录 ABANDONED，第三步重新尝试，最终完成。
5. 修改配置版本后提交，验证旧产物不被复用。
6. 删除或修改成功任务某个阶段的产物，点击“恢复 / 检查产物”，验证损坏被发现并重建。

故障注入参数不进入产物指纹，计算配置版本进入指纹。因此需要使用新素材标识或新配置版本来演示故障；已有有效缓存可能直接命中，故障分支不会执行。

## 定义与依赖

四步串行依赖：VALIDATE → EXTRACT_FRAMES → MOCK_REPLACE → PACKAGE。当前是固定线性 DAG，不是任意图编辑器。每步只有在上游成功且产物校验通过后才能开始。

计算 Mock 用延时和确定性 JSON 产物模拟阶段处理，用可配置异常与合作式超时演示故障。未来替换成真实适配器时，应保留输入、输出、重试和持久化契约。

## 状态与持久化

- tasks：输入素材标识、配置版本、任务状态、故障演示参数、创建时间。
- steps：每步的当前状态、累计尝试次数、预算、下次重试时间、心跳、错误、产物路径与摘要。
- attempts：每次执行的独立记录，状态 RUNNING / SUCCEEDED / FAILED / REUSED / ABANDONED，不用当前状态覆盖历史。
- events：提交、开始、失败、恢复和完成等事件时间线。

任务状态：QUEUED / RUNNING / SUCCEEDED / FAILED。

步骤状态：PENDING / RUNNING / RETRY_WAIT / SUCCEEDED / FAILED。

提交任务和初始化步骤、步骤成功与执行记录更新等操作使用短数据库事务。**不把耗时计算放进数据库事务。**

## 重试与恢复

- 每步默认总尝试预算 3 次，包含首次。失败后采用 500ms × 已尝试次数的线性退避；最大次数后任务失败，下游不执行。
- 失败任务手动恢复时追加三次预算，累计次数和历史保留；不允许对运行中/排队中的任务连续触发手动恢复。
- H2 文件库采用单实例独占访问，不启用 AUTO_SERVER。新进程取得数据库后，将旧 RUNNING 执行标为 ABANDONED，把未完成步骤恢复为 PENDING；已经成功的阶段先校验产物再复用。
- 中断的尝试也计入预算；超过预算不会因重启无限执行。
- 独立调度线程更新心跳，执行线程不负责伪装存活。首版只在重启时恢复，不根据心跳过期抢占仍存活的执行者，不声称支持多实例租约接管。
- 超时只对当前 Mock 的合作式等待有效。真实 HTTP 调用需设置客户端超时，真实子进程需单独终止/确认退出；不能认为 Future.cancel 或数据库改状态就取消了外部计算。

## 产物复用与一致性窗口

指纹由素材标识、配置版本、步骤序号、适配器版本与上游产物摘要计算。**当前素材标识是演示输入，不是实际文件内容哈希；真实文件接入时必须改为内容摘要。**

产物先写同目录临时文件，再原子重命名，最后提交数据库成功状态。SHA-256 用于完整性校验。当前不支持原子移动的文件系统将使步骤失败，不静默跳过保证。

- 成功记录存在，但产物缺失/损坏：重建该步骤并使下游重新校验/计算；未受影响的上游保留。
- 产物已写，但数据库状态未提交：恢复时检查确定性产物，命中后记录 REUSED，不重复 Mock 计算。
- 仅有数据库 SUCCEEDED 不是无条件复用的依据。
- 输入/配置变化不能复用旧结果。

这不是端到端 exactly-once。未来接入外部模型时，远端执行成功但本地没有结果仍可能重复付费，需要供应商幂等键或任务查询/对账等额外机制。

## 查询接口

- POST /api/tasks：提交并返回 202 + taskId。
- GET /api/tasks：任务列表。
- GET /api/tasks/{id}：任务、步骤、全部尝试和事件。
- GET /api/tasks/{id}/artifacts/{position}：校验完整性后读取阶段 JSON 产物。
- POST /api/tasks/{id}/retry：终态任务恢复/检查产物。

提交 JSON 示例：

```json
{"asset":"animation-demo-A","revision":"v1","durationMs":1500,"failStep":3,"failTimes":1,"timeoutMs":30000}
```

## 验证

`mvn test` 验证正常完成、跨任务复用、瞬时失败、重试耗尽、手动重试防并发、模拟的中断记录恢复、配置变更。

`python scripts/smoke.py` 启动独立 Java 进程并调用 HTTP，验证页面、瞬时失败、**真实强杀进程并重启**、产物篡改重建。只终止脚本自己启动的进程，使用独立的 target/smoke-* 数据目录和 18083 端口。结果写入对应目录的 smoke-report.json，服务日志同时保留。可通过 PIPELINE_JAVA 指定 Java 路径。

可选浏览器测试 `node scripts/ui-smoke.cjs` 需要自行安装 Playwright（例如 npm install --no-save playwright）和对应浏览器；Windows 默认使用 Edge。它使用独立 18084 端口，验证页面提交、轮询、重试次数、产物查看和 JavaScript 错误。也可用 PIPELINE_NODE_MODULES、PIPELINE_BROWSER 指定现有测试依赖。Node/Playwright 仅用于此附加测试，正常运行 Java 项目不需要。

## 小时级任务与 GPU 扩展（设计，尚未实现）

- 将真实步骤拆成可持久化的外部作业：提交作业、记录 jobId、轮询/回调状态、拉取产物；避免长时间占用本地线程。
- 心跳、业务执行超时、外部作业超时分别配置。增加取消确认、最大恢复次数和人工干预入口。
- 多实例需要原子领取、租约续期和 fencing/版本校验，旧执行者不能覆盖新执行者的结果。
- GPU 任务声明设备类型、显存需求、优先级与并发配额；排队等待资源不计为执行失败。观测排队时长、GPU 利用率/显存、作业阶段和 OOM 原因。
- 独立步骤应以昂贵计算、稳定产物、可重入性为拆分依据，不按每个函数切割。

## 已知限制与失败分析

- 当前固定四步、单 Worker，同一任务等待退避会阻塞后面的排队任务，尚未实现公平调度。
- 没有真实视频输入、模型调用、GPU 执行器或视觉效果评估。
- 无身份认证、无多实例恢复、无通知推送、无任务取消。
- 临时文件崩溃后可能残留，尚无自动垃圾回收；正式设计应避免误删活跃产物。
- 当前读取完整 JSON 校验摘要仅适用于小产物；大文件应流式计算哈希。
- 内部非业务异常（例如数据库不可写）记录服务器日志并等待后续调度，仍需告警与人工干预；不能保证故障期间自动完成。
